Политика конфиденциальности WorkFlow

Действует с 25 августа 2026 года

WorkFlow — приложение для одного пользователя, которое он запускает на своём компьютере или собственном сервере. Централизованного сервиса, который принимал бы данные пользователей, не существует, и автор приложения не имеет доступа к данным тех, кто его запускает.

Какие данные Google приложение получает

После явного разрешения владельца аккаунта приложение обращается к Google Calendar API:

  • calendar.calendarlist.readonly — список календарей аккаунта: названия, идентификаторы, цвета, признак видимости.
  • calendar.events — события календарей: название, описание, время начала и конца, признак «на весь день», статус, ссылка на серию повторов, служебные поля версии.

Адрес электронной почты подключённого аккаунта приложение берёт из идентификатора основного календаря — чтобы отличать подключённые аккаунты друг от друга. Отдельного разрешения на чтение профиля оно не запрашивает.

Зачем они используются

  • Показать события нескольких аккаунтов в одном окне рядом с задачами.
  • Создавать, переносить и удалять события по действию пользователя в приложении.

Ни для чего другого данные календаря не используются. В частности: не анализируются, не используются для рекламы, не применяются для обучения моделей и не передаются третьим лицам.

Хранение и защита

  • Данные хранятся в базе данных на машине пользователя или на его сервере.
  • Токены доступа Google хранятся в этой базе зашифрованными.
  • Никакой передачи данных на серверы автора приложения не происходит — таких серверов нет.

Отзыв доступа и удаление

  • Доступ отзывается в любой момент на странице myaccount.google.com/permissions. После этого приложение теряет возможность обращаться к календарю.
  • Локальные копии удаляются вместе с базой данных приложения, которой распоряжается сам пользователь.

WorkFlow Privacy Policy

Effective 25 August 2026

WorkFlow is a single-user application that its user runs on their own computer or server. There is no central service receiving user data, and the author of the application has no access to the data of anyone running it.

Google data accessed

With the account owner's explicit consent, the application calls the Google Calendar API:

  • calendar.calendarlist.readonly — the account's calendar list: names, identifiers, colors, visibility.
  • calendar.events — calendar events: title, description, start and end times, all-day flag, status, recurring-series reference, and version metadata.

The email address of a connected account is taken from the identifier of its primary calendar, solely to tell connected accounts apart. No separate profile scope is requested.

How the data is used

  • To display events from several accounts in one view alongside tasks.
  • To create, move and delete events in response to the user's actions in the application.

Calendar data is not used for anything else. It is not analysed, not used for advertising, not used to train models, and not shared with third parties.

Storage and protection

  • Data is stored in a database on the user's own machine or server.
  • Google access tokens are stored encrypted in that database.
  • No data is transmitted to servers operated by the author — no such servers exist.

Revoking access and deletion

  • Access can be revoked at any time at myaccount.google.com/permissions, after which the application can no longer reach the calendar.
  • Local copies are removed together with the application's database, which the user controls.
